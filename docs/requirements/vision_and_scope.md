# SoEasy 桌面全文检索系统 —— 愿景与范围说明书 (Vision and Scope)

> **文档版本**: v1.0.0  
> **编制依据**: Karl Wiegers《软件需求》（第3版）核心框架  
> **基准数据采集环境**: Linux x86_64, GCC 11, Intel Core i7 / 16 线程, 测试工程全矩阵实测数据 (2026-11-07)

---

## 1. 业务需求 (Business Requirements)

### 1.1 业务背景与痛点陈述 (SIBV 模型)

* **情境 (Situation)**：技术开发人员、科研人员与重度办公用户日常在本地存储了数万至数百万的源码、工程日志、Markdown 笔记、Office 文档及扫描版 PDF。
* **问题 (Problem)**：
  1. **内存与系统资源暴饮**：市面现有桌面检索工具（尤其基于 Electron 体系）常驻内存普遍在 300MB ~ 800MB 以上，启动缓慢；
  2. **畸形文件引发整机假死**：损坏的 Word/PDF 或超大二进制文档在解析提取时极易引发内存泄露、无限死锁甚至主程序段错误崩溃；
  3. **数据隐私泄露隐患**：依赖云端同步或上云向量检索的商业工具存在重大的商业秘密与个人隐私泄露风险；
  4. **检索响应迟钝**：大量本地工具缺乏双数组字典树分词与倒排索引优化，万级文件模糊检索出现明显卡顿。
* **影响 (Implication)**：用户被迫关闭搜索常驻后台，在急需查找关键历史文件时浪费大量时间，或承受个人重要代码与财务隐私外泄的法律与商业风险。
* **效益 (Benefit)**：提供一款纯原生、零上云、常驻极轻量、多进程崩溃自愈的低常驻内存（$\le 60\text{MB}$）、毫秒级响应离线检索底座。
* **愿景 (Vision)**：让每一台 PC 都能拥有安全可靠、毫秒级响应、永不假死的离线专属检索大脑。

### 1.2 商业目标与成功指标 (Success Metrics)

基于自动化集成测试套件（`test_comprehensive_matrix`, `test_storage_engine`, `test_watch_and_index`, `test_dat_jieba`）在当前硬件上的实时采集结果，建立以下量化指标体系：

| 指标代号 | 质量属性与度量项 | 实测实际数据 (Measured) | 目标基准线 (Target Baseline) | 阻碍/失败线 (Failure Threshold) |
| :--- | :--- | :--- | :--- | :--- |
| **MET-MEM-01** | **主进程空闲内存 (Idle RSS)** | **54.20 MB ~ 54.23 MB** | $\le 60.0\text{ MB}$ | $> 100.0\text{ MB}$ |
| **MET-MEM-02** | **高负载批量索引期内存** | **54.24 MB** (Worker 闲时淘汰) | $\le 70.0\text{ MB}$ | $> 120.0\text{ MB}$ |
| **MET-LAT-01** | **万级在存文件模糊秒搜耗时** | **1.65 ms** (1649.69 μs / 10,000 files) | $\le 3.0\text{ ms}$ | $> 10.0\text{ ms}$ |
| **MET-LAT-02** | **FTS5 全文首检响应延迟** | **0.054 ms ~ 0.262 ms** | $\le 1.0\text{ ms}$ | $> 5.0\text{ ms}$ |
| **MET-THR-01** | **文本/源码批量索引吞吐率** | **1495.9 文件/秒** | $\ge 1000\text{ 文件/秒}$ | $< 300\text{ 文件/秒}$ |
| **MET-THR-02** | **Zstd 原文解压吞吐率 (单核)** | **6944.18 MB/s** (0.029 ms / 210KB) | $\ge 3000\text{ MB/s}$ | $< 1000\text{ MB/s}$ |
| **MET-ROB-01** | **Worker 崩溃自愈与槽位恢复** | **100% 存活，残留文件 0** | 100% 存活，无残留 | 主进程随之崩溃或槽位泄漏 |
| **MET-RES-01** | **进程文件描述符优化上限** | **1048576** (免 root 提升至 rlim_max) | $\ge 65536$ | $< 4096$ |

## 2. 项目范围与边界 (Scope and Limitations)

### 2.1 包含范围 (In-Scope)

1. **核心解析与检索格式**：
   * 纯文本与工程源码（txt, md, json, xml, c, cpp, h, py, java, go, rs, sh 等）；
   * 现代与传统 Office 复合文档（docx, pptx, xlsx, doc, ppt, pdf）；
   * 离线图片文字 OCR（jpg, png, bmp，内置 ONNX OCR 轻量模型）。
2. **多进程沙箱隔离 (Three-Tier Sandbox Architecture)**：
   * GUI 主前端进程：负责视图渲染与即时交互响应，不执行任何重型 I/O 与解析；
   * Service 主服务：负责调度、去抖、SQLite3MC 索引读写与拓扑去重；
   * Worker 沙箱进程池：承载 Office 解析与 OCR，通过共享内存零拷贝交换，出现崩溃或死锁时被主进程自动回收并自愈重启。
3. **密态安全底座**：
   * 存储层全局采用 SQLite3MC (AES-128-CBC) 进行页级物理加密，裸数据库文件 0 明文泄露。
4. **变动感知与增量索引**：
   * 具备多盘与自定义工作目录实时监听能力，内置 150ms 聚合去抖动，自动捕获动态新增、修改、删除与重命名事件。

### 2.2 坚决排除的范围 (Excluded-Scope，防止需求蔓延)

为了坚守极轻量、高稳健、纯本地的核心价值，本项目明确界定以下功能为**当前版本明确排除**的范围：
1. **坚决零上云**：不提供任何基于互联网的云端同步、第三方遥测上传或中心化用户账户系统；
2. **当前不进行深层递归压缩包解压**：不直接解压并索引包含海量嵌套文件的压缩包（zip, 7z, rar 等），防止恶意“压缩包炸弹 (ZipBomb)”引发磁盘与内存枯竭；
3. **不做网络挂载盘（SMB/NFS/WebDAV）的深度实时监听**：仅保障本机物理硬盘（SSD/HDD）的确定性监控性能，避免网络抖动导致文件监听句柄阻塞挂死；
4. **不引入重型前端容器**：严禁采用 Electron、CEF 等 Chromium 内核框架，界面层严格限制为极低资源开销的 Qt5 Widgets 纯原生实现。

## 3. 环境与实施约束 (Environmental Constraints)

1. **权限边界契约 (CON-PRIV)**：
   * 系统必须能够在**普通受限非特权用户**身份下完整运行；
   * 严禁在运行期执行交互式 `sudo`；
   * 当系统级资源（如 Linux `/proc/sys/fs/inotify/max_user_watches`）配额不足时，系统降级为只读诊断模式，并向用户提供可在宿主机执行的终端配置命令。
2. **内存物理天花板契约 (CON-MEM)**：
   * 主进程常驻物理内存必须控制在 60MB 以内，通过 mmap 共享内存与 DAT 紧凑双数组字典树消除动态堆内存开销。
3. **跨平台兼容契约 (CON-OS)**：
   * 源码严格兼容 Linux (GCC 9+, glibc) 与 Windows 10/11 (MSVC 2019+, Windows CRT)。
